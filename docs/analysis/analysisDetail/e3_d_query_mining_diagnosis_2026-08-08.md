# E3-D Query Mining 诊断：为什么 0 个 slot 通过门禁（2026-08-08）

## 背景

`train-mined-v2` 自构建以来始终 `enabled_slot_count=0`，导致 E3-D/E3-F 长期暂停。此前只知道"没有 slot 通过"，未诊断是**门禁过严**还是**挖掘方法本身不够强**。本次直接运行 builder 并逐 slot 检查验证指标。纯离线，无 LLM 成本。

方法：`scripts/build_e3_f_query_mining.py` 从 9,428 条 train SQL（解析成功 9,428、失败 0）挖掘 question n-gram → SQL 结构 slot 的确定性规则，按数据库做 5 折留出交叉验证。门禁：跨库总精度 ≥0.95、验证预测数 ≥50、各有效 fold 精度 ≥0.90。

## 结果：没有任何 slot 接近门禁

| slot | 预测数 | 覆盖率 | 精度 | 未通过原因 |
|---|---:|---:|---:|---|
| `output_count` | 3853 | 40.9% | 0.906 | 精度<0.95；fold f1=0.89, f2=0.90, f4=0.89 |
| `aggregate_COUNT` | 699 | 7.4% | 0.857 | 精度<0.95；4 个 fold <0.90 |
| `limit` | 621 | 6.6% | 0.889 | 精度<0.95；fold f1=0.87, f4=0.85 |
| `order_by` | 576 | 6.1% | 0.873 | 精度<0.95；3 个 fold <0.90 |
| `order_direction` | 384 | 4.1% | 0.875 | 精度<0.95；3 个 fold <0.90 |
| `join_count` | 313 | 3.3% | **0.610** | 精度<0.95；全部 5 个 fold 在 0.46–0.69 |
| `predicate_GT` | 249 | 2.6% | 0.928 | 仅精度<0.95（fold 全部通过） |
| `predicate_LIKE` | 83 | 0.9% | **0.084** | 近乎随机 |
| 其余 20 个 slot | ≤59 | ≤0.6% | — | 预测数不足 50，多数为 0 |

**最高精度是 `predicate_GT` 的 0.928，最高覆盖率是 `output_count` 的 40.9%（其余全部 ≤7.4%）。** 若把门禁从 0.95 放宽到 0.92，仅 `predicate_GT` 一个 slot 通过，而它只覆盖 2.6% 的问题。

## 决定性检验：即使放行，规则也不比模型自己强

放宽门禁是否值得，取决于挖掘规则是否优于模型自身判断。`output_count` 是唯一同时具备高覆盖率（40.9%，比第二名高 6 倍）和可直接对照基线的 slot，用 E3-C run3 的 197 题实测：

| 对比项 | 数值 |
|---|---:|
| 模型自己判定输出列数桶正确 | 164/184 = **89.1%** |
| 　仅在答错的题上 | 90/110 = 81.8% |
| 挖掘 slot `output_count` 精度 | **90.6%** |
| 挖掘 slot 覆盖率 | 40.9% |

**规则只比模型强 1.5 个百分点。** 期望收益 = 1.5% × 40.9% ≈ **+0.6pp**，在 197 题上约 1.2 道题。

对照本项目自己的判定标准与实测噪声：

- 计划 §4.6 规定"小于约 2 pp 的单次变化只能称为趋势"——+0.6pp 远低于该线；
- 此前 Prompt 扰动的实测副作用量级为 ±4 道题（字面量核实 N=44 净 −4；JOIN 精简 v2 在 26 题上净 0 但含 2 处无关回退）；
- 且 `bird_1480` 曾在两个完全不同的机制下以相同症状回退，说明样本内存在对任意 Prompt 扰动敏感的题目。

**结论：期望信号（约 1 道题）小于注入该信号本身所引入的扰动噪声（约 ±4 道题）。** 这不是"再调调门禁就能用"，是信号强度本身不足。

## 根因：n-gram → SQL 结构，赢不过强模型对问题的理解

当前挖掘的特征是问题文本的 unigram/bigram/trigram/4-gram 加首词标记，目标是预测 SQL 结构 slot。也就是说，它在用**词频统计**做"从问题表述推断查询结构"这件事——而这恰恰是 `gpt-5.4-mini`（`reasoning_effort=high`，每题约 7,800 reasoning tokens）已经做得相当好的事（输出列数 89.1%）。

`join_count` 精度 0.610、`predicate_LIKE` 精度 0.084 进一步说明：越是依赖 schema 与语义的结构维度，表层 n-gram 越无能为力。

**门禁的设计是对的**：它正确地拒绝交付"不比模型现有判断更好"的建议，并在无合格规则时 abstain。0 slot 通过不是门禁的缺陷，是挖掘方法的诚实结论。

## 建议

1. **不要为了让 slot 通过而放宽门禁。** 放宽后唯一通过的 `predicate_GT`（0.928/2.6%）覆盖面过小；把 `output_count` 放进来则会交付一个只比模型强 1.5pp 的建议，期望收益低于扰动噪声。
2. **E3-D 按当前方法判定为不可行，与 E5-B/E6 同类归档**（机制的前提/信号强度不成立，而非排期问题）。E3-F（完整 Offline 系统集成）随之继续暂停，因其依赖 E3-D 产出可用 artifact。
3. **若日后重启，挖掘目标应当改变。** 当前目标"问题表述 → SQL 结构"与模型能力重叠，注定边际收益微薄。真正可能有价值的是**数据集书写约定**——F-Audit 已确认存在跨 4 个数据库反复出现的系统性 gold 模式（最典型的是"问'多少个 X'时在一对多 JOIN 后是否使用 `COUNT(DISTINCT)`"）。这类约定不是通用 SQL 知识，模型没有理由先验知道，且从 train split 挖掘符合本项目的来源合规要求。但需注意其性质：这是在学习标注约定而非查询语义，报告时应如实说明。

## 与项目主论点的关系

本结论补齐了 `../SYNTHESIS.md` §2.3 的最后一块：在"信息类干预"这一唯一被验证有效的类别里，E3-C（Offline Schema Context）成功，而 E3-D（Query Mining）失败。两者的差别很清楚——E3-C 提供的是**模型无法从问题文本推断的数据库事实**（表结构、字段语义、PK/FK 路径），E3-D 试图提供的是**模型已能从问题文本自行推断的结构判断**。

由此得到一条更具一般性的表述：**信息类干预的收益，取决于所供信息是否为模型不可自行获得的；重复模型已有能力的信息不产生收益，无论其统计验证多严格。**
