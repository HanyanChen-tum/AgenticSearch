# 推理轨迹追踪实验计划（2026-08-12）

对齐 8/11 Praktikum 会议 Harshal 的要求：不满足于结果层面的统计结论（哪种 SQL 结构对错率高），
要看模型推理过程本身。方法参照 Thought Anchors（Bogdan et al. 2025, arXiv 2506.19143）。

## 论文方法 vs 本项目能做到的

| 论文方法 | 论文怎么做 | 本项目能否做 |
|---|---|---|
| 句子级分段 + 8 类标注（PS/PG/FR/AC/UM/RC/SC/FAE） | 逐句切开原始 CoT | **能做近似**：拿到的是模型自己生成的带标题分段（`reasoning_sections`），比逐句粗一档，但可以做同样的阶段分类 |
| 反事实重采样重要性（换掉一句话，重采样 100 次，测 KL 散度） | 直接在裸 token 序列里任意位置截断重采样 | **能做粗粒度版**：只能在"轮次边界"（工具结果返回后）截断重采样，做不到句子中间截断，因为总结段落背后的隐藏推理状态不可控制、不可编辑 |
| 注意力头分析（receiver head） | 需要模型内部 attention 矩阵 | **做不到**：闭源 API 不开放 attention，这不是成本问题，是接口权限问题；要做到只能换开源权重模型，那是另一个实验 |

结论：本计划做"轮次级"而不是"句子级"的 Thought Anchors，这个限制要写进最终报告方法论部分，不能含糊。

## 样本范围

主体语料：`core197`（`results/e3_c_conv_core197_run1.json` 的固定 197 题子集，即整个项目一直用的对抗子集）。
当前最优配置（e3-c-conv-rules）下核对结果：**111 错 / 86 对**，全部 197 题都抓取完整推理内容，不再像上一轮那样只挑 8-11 题。

若某个语义模式（例如"两张相似表之间选错"）在 197 题里实例数不够做统计（少于约 15-20 例），
从 dev500 剩余约 303 题中按同一模式定向补充，而不是止步于 197。

## Phase 1：推理内容全量抓取（进行中）

- 升级 `capture_reasoning.py`：加并发（多线程调用 API）+ 断点续跑（每题完成立即写盘，重跑自动跳过已完成的），
  避免 197 题的大批量调用中途失败导致全部丢失
- 对全部 197 题跑 `turn=1`（复现决定结果的第一次生成）、`reasoning_effort=high`，与之前已抓的 11 题设置一致，可以直接合并
- 输出：`docs/analysis/analysisDetail/reasoning_capture_core197.json`

## Phase 2：单题时间线图（自动化生成）

- 写脚本把每题的 `reasoning_sections` 自动转成一条节点序列（先不带 resampling 权重，只做结构化 + 规则标注候选转折点，
  例如"提到了两张表名""改变了对某个词的理解""从不确定变确定"）
- 产出：每题一个结构化 JSON（节点序列 + 候选转折点标记），供人工挑选进一步做 Phase 3

## Phase 3：轮次级重采样（量化重要性）

- 3a：先在 `bird_959`（已读出"想对了又推翻"的案例）上跑通方法——在转折轮次前截断对话，重采样 N=10 次，
  测最终 SQL/答案的分布变化，验证脚本和方法没问题
- 3b：验证通过后，铺开到 Phase 2 筛出的其他候选转折点（不是对 197 题每个轮次都做，优先做有转折信号的）

## Phase 4：跨题统计

- 把 Phase 3 测出的重要性数值，按"轮次在做什么"分类聚合（schema 探索 / 取值确认 / 最终定稿 / 自我怀疑与推翻）
- 检验是否有某一类系统性地更重要，对应论文"规划类步骤比计算类步骤更重要"的结论

## Phase 5：语义决策点重建 Sankey

- 把 Phase 2-4 验证过的语义决策点，替换掉现有 `decision_paths.html` 里那些 SQL 表面特征节点（查询结构、输出宽度等）
- 时间线图（单题内部）和 Sankey（197/500 题汇总）从此共用同一套语义决策点，不是两套互不相关的东西

## 边界与风险

- 论文的逐句 + attention 分析在闭源 API 上做不到，本计划做到的是"轮次级"，这一点要如实写进报告
- Phase 1 是一次性大批量付费调用（197 次 reasoning_effort=high 生成），已与用户确认不设预算/时间上限
- Phase 3 的重采样成本更高（每个候选转折点 N=10 次生成），只对验证过有意义的候选点做，不对全部题目铺开
