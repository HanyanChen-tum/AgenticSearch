# 稳定失败的逐题根因审计（2026-08-08）

## 调查对象与方法

`../analysisDetail/failure_decomposition_2026-08-08.md` 识别出 **77 条稳定失败**：E3-C 的失败题中，未被机械 gold 缺陷检测器标记、且在**全部六个已完成配置**（E0×2、E3-A、E3-B、E3-C、E4-A）下无一例外答错的题目。该文档当时把它们表述为"稳定的能力缺陷"。

**抽样**：按数据库分层，每库取最多 3 题，共 **31 条**（覆盖全部 11 个数据库）。

**判定方法**：逐题读取 question、evidence(Hint)、gold SQL、predicted SQL 及两者的实际执行结果，判定"模型以为问的是什么"与"题目实际问什么"的差异来源。**对涉及"gold 有误"的判定，一律构造对照 SQL 实际执行验证**，不接受仅凭阅读的推断（该原则来自 `../analysisDetail/schema_join_diagnosis_2026-08-07.md` §3.2 的教训——当时仅凭阅读做出的三条"可能等价"判断后来被执行全部推翻）。

## 结论：所谓"稳定能力缺陷"，实际只有约 10% 是能力问题

| 根因 | 题数 | 占比 | 题号 |

| 真实语义歧义 | 1 | 3% | 533 |

## 一、gold 缺陷（32%）——三条已执行验证

### `bird_1029`：gold 用了 ASC 回答"最高"

> 问："**最高** build Up Play Speed 的前 4 支球队的速度是多少？"

```
gold:  ORDER BY buildUpPlaySpeed ASC  LIMIT 4  ->  [20, 20, 20, 23]
DESC （题目所问）                      ->  [80, 78, 78, 77]
```

**gold 返回的是最低的四个。** 模型返回 80/78/78/77 被判错。

### `bird_879`：gold 对文本列做字符串排序

> 问："跑出最快单圈**速度**的车手是哪国人？"

```
fastestLapSpeed 列存储类型          ->  text
gold（字符串排序 DESC）              ->  Italian,  '91.610'
CAST 为数值后排序                    ->  Brazilian, '257.320'
```

**91 > 257 只在字符串比较下成立。** 模型做了数值转换，被判错。

### `bird_218`：gold 的百分比逻辑与题意不符

> 问："致癌类分子中**不含氟**的占比是多少？"

```
致癌分子总数                        ->  152
其中不含任何氟原子的分子数           ->  151
正确答案 151/152                    ->  99.34%   （模型答案）
gold                                ->  100.0%
```

gold 统计的是"含有任一非氟原子的分子"（几乎全部），而非"不含氟的分子"。

## 二、输出约定未指定（29%）

这些题目模型的**计算完全正确**，只是返回了不同的列或标识符。题面没有规定该返回哪一个，两种选择都合理。

| 题号 | 问题措辞 | gold 返回 | 模型返回 |
|---|---|---|---|
| `bird_340` | "**哪些卡片**有强力闪卡" | `id` | `name` |
| `bird_344` | "列出所有 mythic 稀有度的卡" | `id`（5 行） | `name`（2 行，多个 id 对应同名卡） |
| `bird_17` | "按写作均分排名学校，**显示其 charter number**" | CharterNum, 分数, 排名 | 排名, 校名, CharterNum, 分数 |
| `bird_865` | "**谁**是最年长的车手" | forename, surname（2 列） | `forename \|\| ' ' \|\| surname`（1 列） |
| `bird_586` | "**哪位用户**给帖子加了 50 赏金" | DisplayName **+ Title** | DisplayName |
| `bird_1338` | "十月会议的每笔支出**都通过了吗**" | approved | 支出说明 + approved |
| `bird_1427` | "MU 215 场地活动的**预算类别**是什么" | category **+ type** | category |
| `bird_1168` | "化验完成于哪天，患者当时**多大**" | 日期, 年龄 **+ 生日** | 日期, 年龄 |
| `bird_751` | "列出**至少五个**男性超级英雄的超能力" | 恰好 5 行 | 全部去重结果 |

模式很清楚：**多数情况下 gold 返回的列比问题所要求的更多**（`bird_586` 多返回 Title、`bird_1427` 多返回 type、`bird_1168` 多返回生日），或在 id/name 之间做了未声明的选择。

## 三、指代歧义（13%）

问题中的名词在 schema 中对应**多个同名或近义对象**，题面未消歧。

| 题号 | 歧义词 | gold 指的是 | 模型选的是 |
|---|---|---|---|
| `bird_28` | "DOC type" | `schools.DOC`（代码 `'00'`） | `schools.DOCType`（文字描述） |
| `bird_24` | 学校名 | `frpm.School Name` | `schools.School` |
| `bird_584` | "comments" | `postHistory.Comment`（编辑说明） | `comments.Text`（用户评论） |
| `bird_1166` | "diagnosis" | `Patient.Diagnosis` | `Examination.Diagnosis` |

**这与 `../analysisDetail/schema_join_diagnosis_2026-08-07.md` 发现的近义表/列混淆是同一现象**，此处证实它同样贯穿被归类为"能力缺陷"的题目。

## 四、Hint 与 gold 自相矛盾（6%）

| 题号 | Hint 原文 | gold 实际做法 | 模型 |
|---|---|---|---|
| `bird_219` | `percentage = DIVIDE(SUM(bond_type = '#') * 100, COUNT(bond_id)) where label = '+'` | 改为 `COUNT(DISTINCT 致癌分子)/COUNT(DISTINCT 分子)` | **严格照 Hint 实现** |
| `bird_118` | `Percentage = [(total(amount) & condition) / (total amount)] * 100` | 改为按账户数计数 | **严格照 Hint 实现** |

两题中模型都**忠实执行了 Hint 给出的公式**，而 gold 违背了自己提供的公式。

## 五、模型真实推理错误（仅 10%）

| 题号 | 错误 |
|---|---|
| `bird_1498` | 问"最高的**月度**消费"，模型用 `MAX(Consumption)` 取单条记录最大值，未按月聚合——**粒度理解错误** |
| `bird_95` | "最年轻**且**平均工资最高"，模型用 `= MAX(...)` 的合取条件导致空集，gold 用 `ORDER BY` 取头部 |
| `bird_1175` | JOIN 条件多加了一个日期相等约束，导致结果集为空 |

**这三条才是 harness 或模型能力层面真正可讨论的失败。**

## 影响：需要修正的既有表述

1. **`../analysisDetail/failure_decomposition_2026-08-08.md` 的"77 条稳定能力缺陷"表述不成立。** 按本次抽样比例，其中约 **10% 才是模型推理错误**，约 38% 是 gold 缺陷或 Hint/gold 矛盾，约 42% 是数据集未指定输出约定或指代歧义。
2. **"64% 的失败对整类 系统侧干预免疫"这一结论仍然成立，但原因不同**：不是因为模型能力不足到无法改进，而是因为**这些题目的"正确答案"本身不可由题面推导**——无论多好的 harness 都无法猜中未声明的输出约定，也无法复现 gold 的缺陷。
3. **`../SYNTHESIS.md` 结论三（基准质量发现）应大幅加强。** 此前的证据是 F-Audit 的 40%（定向样本）与标注对齐的 +2.03 pp；本次在**被认定为"能力缺陷"的子集**上，仍有 32% 是可执行验证的 gold 缺陷，另有 42% 是数据集未指定的约定与歧义。

## 对后续实验的意义

**反事实消歧实验（原计划的下一步）需要重新设计。** 原设想是"消除问题歧义后重跑，看多少题转正"，用以量化歧义的因果贡献。但本次审计显示：

- 对 32% 的 gold 缺陷题，消歧无效——问题不在题面，在标准答案；
- 对 29% 的输出约定题，"消歧"实际等于**告诉模型该返回哪一列**，这已经不是消歧而是泄漏答案结构；
- 真正适合消歧检验的只有指代歧义（13%）与真实语义歧义（3%）两类，约 16%。

因此该实验的可测范围远小于预期，建议只在指代歧义类（`bird_28`、`bird_24`、`bird_584`、`bird_1166` 及同类）上做小规模验证，并明确其结论只适用于该子类。
